# Map: Multiplayer Arkanoid

## Destination

An implementation-ready spec for a multiplayer Arkanoid game: split-screen and remote play combinable in one session, up to 4 players (max 4 local per desktop device, max 2 local per mobile device), running in PC/Mac/Android web browsers, controlled by keyboard, mouse, joystick, and touch, with competitive (race/attack/duel) and coop (shared-field/parallel-assist) modes, a single-player mode driven by the bot AI validated in the game-feel prototype, and full Arkanoid content. Every decision locked — buildable by agent sessions with zero further decisions.

## Notes

- Domain glossary: `CONTEXT.md` at repo root — use its vocabulary.
- HITL tickets: invoke /grilling and /domain-modeling. Research tickets: /research subagent.
- Single-player mode in scope (destination redrawn after prototype): bot AI validated in the game-feel prototype drives it — see Single-player mode design.
- Max 4 players per session; local players per device: up to 4 on desktop, up to 2 on mobile; split-screen + remote combinable (e.g. 1 desktop × 4 local, or 2 devices × 2 local).
- All competitive variants (race, attack, duel) and all coop variants (shared field, parallel assist) in scope. Per-mode player-count caps decided in the mode-design tickets.
- Free infrastructure only: P2P (WebRTC), free STUN/TURN. No paid services, no accounts, no matchmaking, no server-side persistence. Persistence = local browser storage.
- Session model: room-code lobby, host-authoritative.
- Touch input required (Android browsers) alongside keyboard/mouse/gamepad.
- Full Arkanoid content (levels + power-ups). Prefer a reusable open-source base if a viable one exists.
- Stack: greenfield, chosen after research tickets resolve.
- Multilingual UI: es-419 + en-US minimum — per-locale string tables, no hardcoded strings (Menus & UI beyond the lobby).

- [Research: free WebRTC infra validation](issues/02-free-webrtc-infra-validation.md) — free infra works: Google STUN + Open Relay free TURN fallback, host-authoritative star (host holds state, ≤3 guest DataChannels, 20-60 Hz ≈ 45 KB/s); risks: Open Relay quota ambiguity, client-embedded TURN key, host tab backgrounding (needs wake lock + Worker tick).
- [Research: reusable Arkanoid base survey](issues/01-reusable-arkanoid-base-survey.md) — build from scratch: no viable open-source base (dead/unlicensed/GPL/tutorial-scale); take content DNA from ball-and-wall (MIT): capsule roster, episode structure, level-as-JSON; headless deterministic fixed-timestep sim with sim/render seam from day one.
- [Research: free hosting & TURN credential issuance](issues/12-free-hosting-turn-credential-issuance.md) — GitHub Pages hosts the game (Cloudflare Pages fallback, itch.io mirror); free Cloudflare Worker issues ~1 h ephemeral TURN creds via Metered's REST API, long-lived key never ships client-side; Worker failure only degrades TURN fallback (STUN-direct still works).
- [Research: browser stack options](issues/03-browser-stack-options.md) — PixiJS v8 + TypeScript + Vite + Vitest: rendering library (not framework) keeps headless fixed-timestep sim a pure TS module, renderer consumes snapshots — the sim/render seam netcode requires; best low-end-Android perf certainty; trade-off: hand-build split-screen composition, accumulator loop, input glue.
- [Research: low-end Android performance targets](issues/13-low-end-android-performance-targets.md) — reference device: entry Android tier (T606/G85/SD680, Mali-G57, 3-4 GB RAM); 60 fps render target / 30 floor (sim stays fixed 60 Hz), ≤10 ms app work/frame, <20 draw calls, dpr capped at 2, Canvas fallback = unsupported-class-only, context loss = resync-from-snapshot.
- [Competitive mode design](issues/04-competitive-mode-design.md) — Race/Attack 2-4, Duel 2-only; match structure, level selection, time cap all lobby-configurable; 5 lives, 0 → level reset (time is the cost); Attack: chain/capture/clear/manual triggers, shared meter + per-type buttons, manual targeting, same-type refresh; Duel: no lives, shared-steal or owned-deflect ball model, most points wins.
- [Coop mode design](issues/05-coop-mode-design.md) — both variants 2-4, max 2 local/device; continuous level-range play-through, no rounds/time cap; shared field: lobby-configured placement (A slices/B edges/C summed shared paddle) + ball model (shared or color-coded per-player), shared life pool, life lost when ball count hits zero, +5-8% ball speed/player (A/B); parallel assist: per-player lives, downed state, assist meter (same mechanic as attack meter) spends on power-up gift/brick clear/life gift, no scaling.
- [Session & lobby flow design](issues/06-session-lobby-flow-design.md) — create/join room-code landing (5-char lookalike-free code); host-only lobby config, all-ready gate + countdown start; no late-join mid-game but lobby-join between matches OK (room lives until host quits); guest drop = 90s rejoin window (frozen paddle, slot held, snapshot resync), expiry = removal (competitive loss / coop slot gone); host drop = session dies, no migration (ADR 0001); competitive no pause, coop any-player pause request via host; rematch/lobby/quit end screens; mode picker validates player count.
- [Input mapping design](issues/07-input-mapping-design.md) — desktop up to 4 local (any mix keyboard/mouse/gamepad, mouse 1 slot), mobile up to 2 (touch = 1 player, 2nd = gamepad); per-method defaults with rebindable keyboard + gamepad buttons; action model = cycle target + fire-type buttons (4 attack / 3 assist); touch = virtual stick + buttons overlay; normalized input frame per sim tick (2D axis, buffered edge events) as the sim/netcode seam; cross-method speed parity normalized (technique → Research: input sync & fairness techniques); pause/quit input split by mode; downed players keep assist-spend rights, no self life gift.
- [Content set: levels & power-ups](issues/09-content-set-levels-power-ups.md) — 33 rounds, round 33 = Doh (Race/coop only, Duel draws 1–32); bricks = standard/silver/gold only; 10 capsules (classic 8 + R + ?; T and warp cut, B = exit-clear speedrun mechanic); deterministic per-level capsule script, zero RNG, ? = next undropped scripted capsule; difficulty knobs in level JSON (base speed, tier bumps ≤15/≤8, silver hits `min(1+floor(round/8),4)`); level = char-grid JSON 13×18 + metadata; classic-accurate scoring table; attack tuning defaults (chain 4/7/10, meter costs 30/25/20/40, magnitudes/durations) marked adjust-after-prototype.
- [Research: input sync & fairness techniques](issues/14-input-sync-fairness-techniques.md) — input relay + state broadcast over WebRTC (guests 60 Hz unreliable+redundant input frames, host 30 Hz snapshots / 60 Hz Duel, host continues on missing input); local paddle = client prediction with error-offset reconcile, remote paddles/ball = interpolation (no ball extrapolation); host tick = timeline (no wall-clock sync); competitive fairness = host-only input delay 3–5 ticks; paddle parity = single Vmax × axis (keyboard/mouse-chase/touch-drag binary ±1, stick proportional w/ deadzone); lockstep/rollback rejected (peer-symmetric authority vs host-authoritative star).
- [Netcode sync architecture](issues/08-netcode-sync-architecture.md) — ADR 0002: host-authoritative input relay + state broadcast; uniform tick-D delay queue incl. host-local players (D=0 coop/all-local); 2 channels/guest (unreliable game + reliable control); binary full snapshots ~600 B @ 30 Hz, no deltas; event ring buffer for one-shot visuals; heartbeat+close disconnect detection → 90 s rejoin via join-with-id + full snapshot; version handshake; input redundancy ~10 ticks + stall decay to 0 axis; host overload → 5-tick catch-up cap + slow-motion w/ throttle warning (validate in prototype).
- [Split-screen rendering & layout](issues/10-split-screen-rendering-layout.md) — fixed-aspect letterboxed fields (classic ~2:1 brick cells, near-square); desktop N-across equal columns, mobile 2-local landscape with orientation-lock attempt, 1-local portrait; shared-field/Duel = single field, no split; per-field HUD strip above each field; remote fields never rendered (HUD-only progress; watch panes = fog); touch overlay floats over bottom corners; thin gutters between regions; two-field low-end render validated in prototype with dpr step-down ladder.
- [Menus & UI beyond the lobby](issues/15-menus-ui-beyond-lobby.md) — settings = Controls/Audio/Display (landing+lobby always, in-session coop-pause Audio/Display only); competitive quit-confirm overlay, sim never pauses; coop pause = who-paused + Resume/Settings/Quit options; end screens = winner banner + standings (competitive) / outcome + team score + per-player counters (coop); HUD strip = name/lives/score/round/meter+target, shared-field = single strip; remote progress = top strip rows, numbers only; target display = chip in strip, cycle flashes; touch overlay = left stick + right context cluster (Launch / 4 attack+cycle / 3 assist+cycle), downed keeps assist live; names = "Player N" default, lobby-editable, localStorage; multilingual es-419 + en-US (auto-detect, string tables, single Latin-1 BitmapText atlas, per-device never synced); audio controls ship now, content scope stays fog.
- [Remote competitive fairness: trust model](issues/17-remote-competitive-fairness-trust-model.md) — ADR 0003: trust the host fully — no guest-side checks/warnings/enforcement (impossible + false positives); structural validation both directions mandatory (input clamps/dedupe/rate cap; malformed snapshot = clean protocol-error end, never crash); host-only kick at both moments (lobby + mid-session via removal semantics); lobby join auto-accept, stranger handled by kick; spec carries accepted-risks section (host tamper/fabricate/withhold, guest mod/flood/stall/spam bounds, code-guessing).
- [Game-feel prototype](issues/16-game-feel-prototype.md) — modes + netcode feel right in practice; prototype validated: prediction + error-offset reconcile (incl. duel paddle-as-wall), box-overlap ball/capsule collision, owner-colored balls for Duel ownership readability, host-view rendering (interpolation guest-only), wall-constrained paddle separation, multiball drop = only last ball re-attaches; bot AI good enough to drive single-player (destination redrawn to include it); tuning values confirmed as shipped defaults.
- [Research: free signaling for room-code join](issues/18-free-signaling-room-code-join.md) — Cloudflare Worker + SQLite Durable Object per room (`idFromName(code)`, WebSocket Hibernation — idle host socket free, ~10k sessions/day in free tier); front door validates code charset + Origin; guest closes signaling WS once DataChannel opens (DO never sees game data); fallback = manual copy-paste (non-trickle SDP, gzip+base64, auto-offered on WS failure); public brokers/PeerJS/key-embedded services rejected (no SLA / squatting / burnable key).
- [Single-player mode design](issues/19-single-player-mode-design.md) — both shapes: solo episode (classic 3 lives, 33 rounds, continue-on-game-over, localStorage high score, no lobby) + versus bots (all variants, 1 human + N bots only, trimmed config screen, 3-level parametric difficulty); same host-authoritative pipeline, bot = host-local input source, D=0; pause freely (coop semantics).
- [Skin & theme system design](issues/21-skin-theme-system-design.md) — player skins (paddle+ball, shape/texture not color) + host-chosen field themes (brick set + background); Settings default + lobby override; skin id = UUID (collision-free), full id at join → compact session index in snapshots; synced via session state; Duel ownership outline stays as orthogonal validated layer; richer audio set (per-event SFX variants, jingles, level/boss music) sourced per asset research.
- [Research: free asset libraries for skins, themes & audio](issues/20-free-asset-libraries-skins-themes-audio.md) — all-CC0 recipe covers the whole skin/theme/audio system, no commissioned art: Kenney + Buch OGA Breakout set + Tiny Break-em (sprites), Junkala 512 SFX + 5 chiptunes + SketchyLogic NES (audio), jsfxr for gaps; custom-author lettered capsules, Doh sprite, brick hit-states; CC0-only commit rule (CraftPix/freepd/GPL/CC-BY excluded), zero attribution obligation.
- [Assemble implementation-ready spec](issues/11-assemble-implementation-ready-spec.md) — spec assembled at spec.md, decision-complete: all fog settled (audio richer set, QR in scope, watch panes post-spec), deferred values locked (field 208×256, economy defaults, pool 3×players, Continue −60%, bot table), [authoring] markers = data-only; human review passed 2026-09-02 (one amendment: Playwright e2e in §3/§17).

## Out of scope

- Accounts, matchmaking, global leaderboards, any server-side persistence — free infra, local storage only.
- Paid infrastructure of any kind.
- Native desktop or mobile builds — web browsers only.
- ~~Single-player mode or vs-AI~~ — **ruled back in scope**: destination redrawn after the game-feel prototype validated the bot AI; now [Single-player mode design](issues/19-single-player-mode-design.md).
- Bots alongside more than one human (split-screen + bots, remote session + bot slot-fill) — single-player sessions are exactly 1 human + N bots; ruled by [Single-player mode design](issues/19-single-player-mode-design.md); post-spec candidate.
- Watch panes (scaled-down live remote fields) — game-feel prototype did not flag Race as blind without them; post-spec candidate.
