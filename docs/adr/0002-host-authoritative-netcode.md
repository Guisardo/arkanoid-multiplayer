# Host-authoritative input relay + state broadcast netcode

Multiplayer Arkanoid runs host-authoritative over WebRTC DataChannels: guests send 60 Hz input frames on an unreliable+redundant game channel, the host simulates at a fixed 60 Hz and broadcasts 30 Hz binary snapshots (60 Hz for Duel); guests predict only their local paddle and interpolate remote kinematics. Lockstep and GGPO-style rollback were rejected because peer-symmetric authority contradicts the host-authoritative star (ADR 0001), and lockstep couples all players to the most lagged one.

## Consequences

- **Uniform input pipeline:** host-local players' input frames pass through the same tick-D delay queue as guest frames (D = 3–5 ticks, competitive only, default 4 ≈ 66 ms; coop D = 0; all-local sessions D = 0) — the host device skips only the network hop, never the delay, so no player has a shorter pipeline than another. Residual guest-vs-guest RTT asymmetry is accepted; full parity would need rollback (rejected, documented as a v1 upgrade path for Duel).
- **Two channels per guest:** game channel (unreliable, unordered — input frames guest→host, snapshots host→guest) and control channel (reliable, ordered — lobby, rejoin, pause, version handshake). Binary wire format on the game channel (full bit-packed snapshot ≈ 600 B ≈ 18 KB/s/guest at 30 Hz, fits the ~45 KB/s budget); JSON on the control channel.
- **Full snapshots, no deltas:** every broadcast tick carries the complete state — tick number, phase, per-player ack of latest input frame seen, kinematics (paddles, balls, falling capsules), snapped state (brick grid, scores, meters, effect timers), and a small event ring buffer (last 8 events with source/target/tick) for one-shot visuals like brick rain. Delta machinery was rejected as complexity and desync risk at a data rate that fits the budget without it.
- **Loss behavior:** input frames ride with a ~10-tick redundancy window (validate after prototype); snapshots carry no redundancy — guest interpolation buffer (latest − ~2.5 intervals, adaptive) absorbs gaps. Host decays a silent guest's axis to 0 after ~10 missing ticks so a stalled paddle stops rather than runs away; genuine disconnects are caught by heartbeat (guest ping every 5 s, drop declared at ~10–15 s silence) or DataChannel close, whichever fires first, opening the 90-second rejoin window.
- **Host stall:** catch-up cap of 5 sim ticks per render frame; sustained host overload degrades to slow-motion rather than freezing or spiraling. Warn the player when throttling is detected (sustained catch-up) — validate in prototype.
- **Guest blind period:** local prediction keeps running, remote entities freeze at last interpolated state, reconnect banner after ~1 s snapshot silence; session-over only when the control channel closes or silence hits ~10–15 s (host drop = session dies, ADR 0001).
- **Rejoin:** guest re-sends join with original player id on the control channel; host validates the held slot, replies with rejoin-ack + full snapshot; guest rebuilds scene, wipes prediction history. Protocol version int in the join handshake — mismatch refuses join with a "refresh your browser" message.
